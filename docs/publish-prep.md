# Publish preparation

This document records the release order and checks required before publishing.

## Unified versioning

Every package under `packages/` shares one version. The `vX.Y.Z` tag is the
source of truth; `.github/workflows/release.yml` verifies each `package.json`
version equals the tag before publishing.

## Release order

Packages with no cross-package runtime dependency publish independently, but
the family is versioned and published together for a single coherent release.
The publish pipeline runs `pnpm -r publish` in workspace dependency order.

## Pre-publish checks

- `pnpm typecheck && pnpm test && pnpm build` is green (or `mise run ci`, which
  adds the runtime-deps and docs checks).
- `pnpm runtime-deps:check` passes (no published bundle imports a
  devDependencies-only package).
- `pnpm docs:check` passes.
- Every package version equals the release tag.
- Release notes exist at `docs/release-notes/<tag>.md` or are generated by the
  pipeline fallback.

## npm tokens

Publishing uses the repository secret `NPM_TOKEN` (an npm automation token for
the `@dsh-next` scope). Never commit token configuration; keep it in the user
`~/.npmrc` or CI secrets.
