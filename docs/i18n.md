# Bilingual README contract (i18n)

Every package README is maintained as an English/Simplified-Chinese pair with
equal authority. A pair is three flat files in the package directory:

| File | Role |
| --- | --- |
| `README.md` | English side |
| `README.zh.md` | Chinese side |
| `README.i18n.yaml` | Pairing record: the git blob hash of each side |

## How the pairing record works

`README.i18n.yaml` stores the `git hash-object` blob hash of both sides as of
the last confirmed-consistent state. Blob hashes are content-addressed and
commit-independent: editing either side invalidates the record, and
`pnpm docs:check` fails until the pair is consistent again. The mechanism
guards against translation drift - one side getting edits the other silently
misses.

## Maintenance flow

1. Edit either side (both languages carry equal authority).
2. In the same change, mirror the edit into the other language so facts and
   structure stay identical.
3. Re-record the pairing hashes once both sides agree:

   ```sh
   pnpm docs:write-pair <slug>   # e.g. cc-plugins
   ```

The resulting yaml diff in the commit is the auditable "both sides confirmed
consistent" action.

## Structural mirror

Apart from translated text and the switcher lines, both sides must mirror:

- heading levels and order (heading text is translated, structure is not);
- fenced code blocks one-to-one, with identical content and language tags
  (comments inside code samples stay English);
- table row and column counts;
- list kinds and item counts;
- link targets (the switcher lines are the only intentional difference).

Switcher lines sit directly under the H1: `English | [中文](README.zh.md)` on
the English side, `[English](README.md) | 中文` on the Chinese side.

## Gate

`pnpm docs:check` (`scripts/verify-docs.mjs`) verifies mechanically: triplet
presence, switcher lines, signature mirror, and that recorded hashes match
current content. The gate proves "both sides matched at record time"; it does
not judge translation quality, which stays with review. `pnpm docs:list`
reports pair state without failing.

## Scope

- Covered: `packages/*` READMEs. The `pnpm plugin:new` scaffold creates the
  full triplet, so new packages are bilingual from their first commit.
- Not covered: `docs/`, repository-level files, and `docs/archive/`, which
  stay English only per `docs/AGENTS.md`.

## Plugin UI strings

User-facing strings in a plugin's browser half are bilingual under the same
equal-authority rule as READMEs, enforced by `pnpm i18n:check`
(`scripts/i18n-check.mjs`):

- `src/client/dictionaries/en.ts` - the key source: dotted keys grouped by
  area, English copy, the `MessageKey` union, and the namespace constant
  `NS` (convention: the bare plugin slug);
- `src/client/dictionaries/zh.ts` - the Simplified Chinese mirror,
  compile-checked against the same key union;
- `dictionaries.ts` - the public barrel, plus the standalone interpolation
  and no-locale English fallback helpers.

Wiring rides the platform `locale` service and nothing else: register with
the typed `ctx.locale.register(NS, { en, zh })` inside `ctx.effect` (both
locales in one compile-checked call; duplicate registration throws, so guard
with try/catch for idempotent re-apply), translate with `ctx.locale.bind(NS)`
(a stable, typed translator reading the active locale at call time), and give
slot registrations a function label carrying `locale: NS` so language
switches re-render them.

The platform provides the rest out of the box and must not be re-implemented:
the lookup chain (namespace -> en -> the shared `common` vocabulary -> the
key itself, failing loud), `{name}` interpolation, the durable language
preference, the Language row UI, and live re-render on switch.

Scope and boundaries:

- The gate enforces the mandate (client `.tsx` implies dictionaries exist),
  zh/en key parity, `{placeholder}` parity, and no CJK text outside
  dictionary files (per-line exemption: `// i18n-allow: <reason>`).
- Host-side strings (install notes, host-generated toasts and errors) stay
  English: they persist on records and are quoted in diagnostics.
- On-screen literals of third-party tooling quoted in a UI (Claude Code
  labels a card displays verbatim) stay English inside inline code.
- Reference implementation:
  `packages/dsh-next-cc-plugins/src/client/dictionaries/`.
