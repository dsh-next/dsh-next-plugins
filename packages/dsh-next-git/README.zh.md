# 面向 DeepSeek Harness 的源代码管理

[English](README.md) | 中文

无需离开 Harness，即可审查更改、保存提交并在分支上工作。

## 安装

- 需要 Harness 0.1.7-alpha.1 或更高版本、Git 2.31+，以及位于 Git 仓库中的会话。
  提交前请配置 Git 提交者姓名和电子邮件。
- **尚未发布：**此包目前为私有包，尚未发布到 npm。
  以下命令供未来发布后使用。

```sh
dsh plugin --profile <name> add @dsh-next/dsh-next-git
```

`<name>` 是你的 DSH 配置档案（例如 `web`）。

## 快速开始

1. 在仓库中打开会话。在右侧边栏的 `Start guide`（罗盘标签页）中，选择 `Source control`。
2. 检查顶部显示的分支名。编辑并保存该文件夹中的一个文件，然后展开 `Changes`。
3. 点击更改的文件查看内容。悬停文件行并选择 `Stage`，将这些更改选入下一次提交。
4. 选择 `Commit`。在 `Commit message` 中输入摘要，空一行后可添加详情，
   然后按 `Cmd`/`Ctrl` + `Enter`。
5. 打开 `History`，即可看到新提交。它只保存在本地，尚未推送。

## 你可以做什么

- 查看文件差异，暂存整个文件或单个代码块（一组更改行）。
- 开始工作前，从侧栏或消息输入框选择分支。
- 创建工作树（独立的工作文件夹），用于另一个分支或会话。
- 查看、比较提交，或用专用编辑器解决冲突。
- 请智能体审查更改或起草提交信息。

## 使用前须知

- `Discard` 无法撤销，并会删除未跟踪的文件。删除工作树会移除其文件夹。
  请检查确认内容，并备份重要工作。
- 历史改写会改变提交 ID，并移除旧签名。改写共享历史需要确认；插件不会自动推送。
- AI 操作会将代码发送给所选模型提供商，可能产生费用。
  请检查共享的文件；敏感文件名筛选无法发现所有秘密。
  星光按钮会直接发送差异，并在成功后替换信息。
- 工作树设置会以你的账户运行项目命令，并可能复制本地文件。
  每次创建都需要分别批准；两者均不会自动执行。

高级任务请阅读[工作树设置、历史安全与故障排查指南](<https://github.com/dsh-next/dsh-next-plugins/blob/main/docs/git.md>)，
本地开发请阅读[贡献指南](<https://github.com/dsh-next/dsh-next-plugins/blob/main/CONTRIBUTING.md>)。
